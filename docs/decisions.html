D33 in detail · built 2026-11-25
  • What happened: on macOS 27.3 the run crashed reading the hotspot's settings (SCPreferences through ctypes, "crashed on child side of fork pre-exec"), then, once that moved to a helper process, at the self-test (urllib's proxy lookup, SystemConfiguration again). Both are fixed on their own (macos/scprefs.py, http.client), but a call-by-call hunt can't keep up with every macOS: a macOS specialist's analysis showed even plain library calls in a forked child are outside Apple's contract.
  • The guarantee: nx_spoof.py start launches its worker as a brand-new process (its own session, its output to the start's file), and the keeper launches the run the same way, with your user, group and groups set by the launch (macos/process.py background / started, macos/privsep.py spawn_run). Each is handed only what it needs: the answer pipe, the lock (the worker), the keeper's socket (the run), and a hand-over pipe for what the start knew in memory; it takes them over (take_over: made private again, so nothing leaks into later programs). The run checks first thing it isn't root and can't become root again.
  • Checks: a canary test does the run's Mac paths in a forked child of a threaded parent (where macOS 15 aborts too), a real fresh child is started in the tests, and a crash names its signal in the keeper's note with macOS's crash report's place. There's no os.fork left in NXSPOOF.
D31 in detail · built 2026-11-24
  • Errors in words: every error line names the error's kind (KeyError: 'name', not just 'name'); an unexpected one keeps its traceback in the line's details, the keeper's included (core/fmt.py). A broken reaction, a hotspot watch that can't look and the dashboard's internal errors used to be silent: each says so once.
  • This Mac: every run's log starts with macOS's version and build, the model, the chip, Python, the language and whether an organization manages the Mac (macos/machine.py). Nothing personal: no Mac name, no user name, no serial number.
  • Quiet sensors: a reworded Wi-Fi log line or a moved lease file breaks nothing loudly, so the end of a run says when one source saw nothing while the others saw consoles (features/sensors.py). A hotspot that never comes up lists the network interfaces macOS has.
  • 🐞 Report: one engine (app/reporting.py, features/report.py), two doors: the dashboard shows it first, then Copy (and Open GitHub once the repository exists); nx_spoof.py report (menu 6 → 4) prints it, saves it, copies it and opens GitHub's page. It goes through the clipboard, never in a web address: too long for one, and nothing personal should travel in one. Skipped: sending it anywhere by itself.
D30 in detail · built 2026-11-21 and 22
  • One start: nx_spoof.py start (was run) from either door: the program copy, setup's checks (--fix, --anyway), run.lock, the background, the run's one answer. Every run plugs the cable in and takes it out at its Stop; it gives up on a hotspot that isn't up after 60 s. Gone: foreground runs, start.sh, the page's Start in Terminal.
  • The dashboard reads files: it finds the run by its lock and follows its records and run_state.json; the run reads settings.json again when it changes. Gone: the run's own page and web API, registering, the relay.
  • Settings trimmed to the consoles plus seven; what only a Terminal run needs is a --flag. The dashboard's port remembered in dash.json, one dashboard at a time. Closing the page during a run asks Stop NXSPOOF / Keep running.
  • The hotspot watch never gives up: 5, 15, 30 s, then every minute.
  • From the first real-Mac checks: a Stop leaves a note (stop.json) as well as a signal (a run born from the password window had its signals blocked); a closed page is noticed in seconds; "already running" at once.
  • The menu redone with numbers on every screen, grouped, grayed out by context; scripts/ trimmed to four files; setup and undo wait while a run is active.
  • The docs (2026-11-22) became these HTML pages, with every table that mirrors the code written from it.
