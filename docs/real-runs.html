Real runs

For after a big change. A simulated session (menu 8 → 2) proves NXSPOOF still behaves exactly like the reference run, but not how it does on your real Mac with your real Switches. These runs do. Each one is checked from its own log afterwards.

Before you start: menu 7 → 1 (is this Mac ready?): everything should say ✅. After each run: menu 6 → 1, or pick the run in the dashboard's log pane: every item ✅; ⏭️ means "not tried in this run" (FTP, for example), which is fine.

Run I: the untangled NXSPOOF on the real Mac

Everything built after Run H, tried for real: Create NXSPOOF.app.command, ⚙️ Configure and its one Save, 🛠️ Save and fix, the log pane's run picker, the hotspot NXSPOOF only reads, Import, and D30: one way to start from both doors, the dashboard finding the run by its lock, the closing dialog, the cable taken out at Stop, the restore that keeps trying, the menu with numbers. About 40 minutes; one Switch is enough.

Phase 0 · before (Claude)

Tell Claude you're starting Run I: Claude copies your data folder aside, and you settle what happens to the 22 runs from before the records (Nov 13 and 14): archived into the history zip, or kept.

Phase 1 · the app maker, on a fresh copy
  1. git clone ~/Documents/nx-spoof ~/Downloads/nx-spoof-i, then double-click Create NXSPOOF.app.command in it. Expected: its window says NXSPOOF.app is ready, the app opens, the dashboard appears (macOS may ask about the Downloads folder: Allow). The window says you can close it.
  2. Close the page. A few seconds later the dashboard closes by itself. The copy is only for this phase (it goes to the Trash at the end).
Phase 2 · Configure, on your usual NXSPOOF.app (nothing running)
  1. The header is one row: the chips on the left; ▶ Start NXSPOOF, 📖 Help and ⚙️ Configure on the right. 📖 Help opens these pages in a new tab.
  2. ⚙️ Configure shows ✋ N: N is the number of ✋ lines in its This Mac column.
  3. The hotspot line says "NXSPOOF", channel 11, with a password; System Settings → Sharing opens the Sharing pane (close it).
  4. On Thunderbolt Bridge's line, pick 10.254.0.1. Expected: the dropdown turns blue, the bar says 1 change not saved, 🛠️ says Save and fix. Press it: one password, then the bridge and the virtual cable are fixed in the same go, and the checks come back ✅.
  5. Open FTP watch, set Port to 0, Save: refused, the line turns red with must be at least 1, got 0, nothing written. Discard: the bar goes away.
  6. 📤 Export settings, then 📥 Import settings… with the file you just downloaded (not an older export: it would put the bridge back to 172.16.0.1): the preview says nothing changes; Import anyway. Expected: a settings.json.before-import-<time> in the data folder, and a SETTINGS imported from a file line.
Phase 3 · a run from the dashboard
  1. ▶ Start NXSPOOF, your password (the window goes away at once; the page shows the run a few seconds later), then READY. The 📡 chip says NXSPOOF · 192.168.2.1. The run's log starts with START setup's checks: this Mac is ready and START virtual cable: plugged in just now (taken out again when NXSPOOF stops) (or already plugged in).
  2. ⚙️ Configure while it runs: This Mac is one line (Setup waits until NXSPOOF stops). Set FTP watch's Recheck When Up Seconds to 45, Save: SETTINGS changed ftp.recheck_when_up_seconds 30 -> 45 from the dashboard (applies now), then within about two seconds the run's own SETTINGS settings.json changed: … (applies now). Put it back to 30. ← Dashboard.
  3. Join the hotspot on a Switch: its test passes. ■ Stop: stop requested from the dashboard, the usual clean stop, and virtual cable taken out if this run put it in.
  4. ▶ Start again, READY, then close the page. About 2 seconds later a macOS dialog (also try quitting the browser instead of closing the tab): NXSPOOF is still running… Keep running: the dashboard closes, the hotspot stays up. Open NXSPOOF.app: the run at once, its whole log from the first line, and the ■ Stop button in the header. Close the page again; this time Stop NXSPOOF: a clean stop, and the dashboard closes. (Opening NXSPOOF.app twice in a row just brings the same page back.)
  5. In the log pane's picker, pick that run: casual lines with the Switch's name in its color, the checklist line ✅ (open it). Technical, then ● Live.
Phase 3b · the menu
  1. menu.command → 1: your password once, then about 10 seconds later ✅ NXSPOOF is running. Connect a Switch to "NXSPOOF" … and the prompt is back. Close that Terminal window: NXSPOOF keeps running. Open menu.command again: 1 is grayed out now (NXSPOOF runs), but pick it anyway: NXSPOOF is already running (process …): nothing done., at once, no password.
  2. menu.command → 4: the casual log, live; Ctrl+C: stopped watching; NXSPOOF keeps running. Then 3, the technical one.
  3. 2: Stop requested…, then NXSPOOF has stopped.; menu 6 → 1 checks it: stopped by nx_spoof.py stop (menu 2).
  4. The keeper's heartbeat: menu 1, wait for the answer, then kill -STOP $(python3 -c "import json; print(json.load(open('$HOME/Library/Application Support/NXSPOOF/run.json'))['pid'])") (it pauses the run). About 30 seconds later the hotspot goes away by itself and the run's log ends with NOTE the run froze (no heartbeat for 30 s), so the keeper ended it - the keeper did: ….
  5. 9 (Docs): the pages open in your browser.
Phase 3c · the hotspot drops during a run (the Nov 18 event, on purpose)
  1. ▶ Start, READY, a Switch connected. In Terminal, take the virtual cable out of Thunderbolt Bridge as macOS did on Nov 18 (your password): sudo ifconfig bridge0 deletem feth0
  2. Within about 5 seconds: the hotspot went DOWN, the 📡 chip turns red, then try 1: virtual cable plugged back in, Internet Sharing turned ON again, the CHECK lines, and the hotspot is UP again … the self-test passed. The Switch rejoins by itself. ■ Stop.
Phase 3d · Fix and start

With nothing running, in Configure, pick another address on Thunderbolt Bridge's line and press Save only: This Mac shows ✋ Thunderbolt Bridge. ▶ Start NXSPOOF: the panel lists it with 🛠️ Fix and start. Press it: one password, setup fixes the bridge (its own …-setup.log), then NXSPOOF starts. ■ Stop, then put your usual bridge back (🛠️ Save and fix).

Phase 4 · the hotspot renamed outside NXSPOOF
  1. System Settings → General → Sharing → ⓘ Internet Sharing → Wi-Fi Options…: rename the network NXSPOOF-I (keep the password). Quit System Settings (⌘Q).
  2. ⚙️ Configure: the hotspot line notes Its name changed since the last run (it was "NXSPOOF").
  3. ▶ Start, READY: ⚠️ Your hotspot is now called NXSPOOF-I (it was NXSPOOF last run); the 📡 chip says NXSPOOF-I. ■ Stop.
  4. Rename it back to NXSPOOF, then ▶ Start and ■ Stop once more: it warns once more (expected). Your Switches find NXSPOOF again.
  5. Back to your usual bridge: Thunderbolt Bridge's line → 172.16.0.1 → 🛠️ Save and fix.
Phase 5 · after (Claude)

Claude reads every log of the run (setup, the runs, the dashboard's) and lists anything odd; ~/Downloads/nx-spoof-i goes to the Trash.

If something shows ❌

The lines under it say why, and the full run is in data/logs/ (last_run.log points to the latest). Tell Claude which run and paste the ❌ lines (Claude can read the logs too). If a run left the hotspot on, the dashboard's banner offers 🧹 Clean up (or menu 7 → 4). python3 -B tools/verify_run.py --all shows which ways of stopping the runs have covered.
