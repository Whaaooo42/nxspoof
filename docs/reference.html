A good run, casual

🚀 Starting NXSPOOF…
📡 The NXSPOOF Wi-Fi is on. Your Mac is offline while it runs.
✅ All set! Turn on a Switch and connect it to NXSPOOF.
🎮 Switch 2 connected
🌐 Switch 2 thinks it's online, all good
🛡️ Switch 2: 4 attempts to reach the internet blocked so far
📁 Switch 2's file server is ready: ftp://192.168.2.3:5000
👋 Switch 2 left (it was here 3 min 42 s)
🎮 Switch 2 is back
🛑 Stopping…
📋 What happened:
   Switch 2: here 5 min 10 s, online check passed 2 times, 6 attempts to reach the internet blocked
🏠 Your Mac is back on your home Wi-Fi. Bye!

Blocked attempts show as a running total, at most once a minute per console (the full list is in the log file). A console that isn't in settings.json shows as 🙋 "A console I don't know just connected". Problems are never hidden: 😕 plus a plain explanation, with the technical line in gray underneath.

A good run, technical

In the Terminal: green for PASS / 200 ok / FTP up, red for BLOCKED, each console's name in its own color only where the line names that console (not inside "Nintendo Switch 2" or "Switch 2 connection test"). On the dashboard, a name takes the console's current color, so older lines follow a color change.

  • Something odd in settings.json (an unknown key, a value out of range): a SETTINGS WARNING … line says what, and which default is used; the run carries on. Options given at start: a SETTINGS from options: … line.
  • A console usually asks for its address twice; the second DHCP line ends with again. An unknown console shows as Unknown console, plus a NEW line.
  • Joining and leaving come from macOS's Wi-Fi driver, which checks a connected console every 5 seconds: left the Wi-Fi about 6 seconds after it leaves (disconnected), 16 at most (no longer seen for 16s). A visit always starts with joined the Wi-Fi, even when the console's first packets beat macOS's line.
  • While it runs, a change to settings.json is said once: SETTINGS settings.json changed: ftp.port 5000 -> 2121 (applies now).

At the stop: the firewall's counts, then a summary per console.

The dashboard

NXSPOOF.app, menu 5, or python3 -B nx_spoof.py dashboard (scripts/dashboard.command: the same with a Terminal window beside it). No hotspot and no password: http://localhost:8800, the same port each time (remembered in dash.json; another only if something else holds 8800). One dashboard at a time: opening it again brings the open page back.

What's allowed (and nothing else)

LayerAllowedEverything else
DNSctest.cdn.nintendo.net (Switch 1) and ctest.p01.ctest.srv.nintendo.net (Switch 2) get the Mac's address0.0.0.0 (BLOCKED); no IPv6 answers at all
Webthose two names: 200 OK + X-Organization: Nintendo + ok, like Nintendo's servers403 (BLOCKED)
Firewalla console may send the Mac: DHCP, DNS (UDP 53), web (TCP 80)dropped: the internet, your home network, other services on the Mac
Routing—shared from a dead link (Thunderbolt Bridge + the virtual cable): no route out at all

Connections your Mac starts are allowed: FileZilla → a console's FTP server works with the firewall on; the console can reply, but it can't start anything itself. The FTP watch uses the same kind of connection.

settings.json

In NXSPOOF's data folder, ~/Library/Application Support/NXSPOOF/settings.json (the data shortcut; menu 6 → 3). Easiest: the dashboard's ⚙️ Configure, which checks every value and saves it in a tidy layout. By hand, JSON is strict: double quotes, no comma after the last item, no comments; a typo stops NXSPOOF with the line and column. Missing: built-in defaults. Options given at start override it for that run.

from the code The settings (now: a running NXSPOOF uses the change within about two seconds; next start: saved now, used from the next start):

Models the dashboard offers: Switch V1 (Erista, unpatched / patched), Switch V2 (Mariko), Switch Lite (Mariko), Switch OLED (Mariko), Switch 2 (CONSOLE_MODELS in settings/schema.py, each with its details as a hint); any other text written by hand is kept. Not settings (D30): what only a run started by hand needs is an option (the firewall, sharing by hand, keeping it on, follow's style and colors), and the dashboard's port is remembered in dash.json. An older settings.json with those keys still loads: they're named as unknown, kept, not used.

The FTP watch: a server that was up counts as down after 3 failed checks in a row. While FileZilla is connected to it, it stays UP (many console FTP apps take one connection at a time): FTP server busy (…) - still UP. Checking means briefly connecting; if your FTP app shows "client connected" each time, set recheck_when_up_seconds to 0.

Export and import: the dashboard's ⚙️ Configure (📤 Export never includes a password: the hotspot's lives in macOS; 📥 Import shows what it would change first), or menu 7 → 5 / 7 → 6: nx_spoof.py settings export ~/Desktop/nxspoof-settings.json, … settings import … (it says what changes and asks; --yes skips the question; refused while NXSPOOF or its dashboard is open). Every import keeps the previous file as settings.json.before-import-<date>_<time>.

Options

from the code For one run (or one command) only. The dashboard on its own takes only --settings: any other option given to it is named once at the top of its log and ignored.

OptionWhat it does
--settings …settings file (default: settings.json in NXSPOOF's data folder, ~/Library/Application Support/NXSPOOF)
--console technical|casualfollow's style (technical by default); the log file is always technical
--no-colorplain text in Terminal (follow; colors are off in a file or a pipe anyway)
--no-firewalldon't load the firewall (for comparison tests)
--manual-sharingyou turn Internet Sharing on and off yourself
--keep-sharingleave Internet Sharing ON when NXSPOOF stops
--no-ftp-watchdon't watch consoles for FTP servers
--open-filezillaopen FileZilla when a console's FTP server comes up
--ip …testing: address to listen on (default: find the Internet Sharing network)
--answer-ip …testing: address given for the connection-test names (default: --ip)
--dns-port Ntesting: DNS port
--http-port Ntesting: web port for the fake connection test
--probe …tinkering: these names (comma-separated) get the Mac's address instead of BLOCKED, to see what a console then asks; their web requests are still refused, and logged in full
--anywaystart: even when setup's checks say this Mac isn't ready (the dashboard's Start anyway)
--fixstart: setup's fixes first when this Mac isn't ready, then the start (the dashboard's Fix and start)
--allow-sleepstart: let this Mac sleep during the run (by default a run keeps it awake: the hotspot sleeps with it)
--no-keeperkeep the whole run root in one process (no privilege separation; for comparison and debugging)
--yessetup, uninstall: no questions, the answer is yes (the dashboard's This Mac buttons use it)
--only …setup: fix only these steps, e.g. --only bridge,cable (the others are checked, not fixed)
--skip …setup: never fix these steps, e.g. --skip cable (they're checked and reported)
--to before|defaultsuninstall: what Undo puts back: before (this Mac as it was before NXSPOOF changed it; the default when NXSPOOF has a record) or defaults (macOS's own)
--task …set by the dashboard: a ticket the command writes into its records, so the dashboard follows it
--fullreport: add the whole technical log of the newest run (folded)
--no-openreport: don't open GitHub's new issue page, only print its address
