The two doors

One NXSPOOF, two ways in: NXSPOOF.app (the dashboard, for everyone) and the Terminal (menu.command, nx_spoof.py and its --flags, for whoever likes to see under the hood). Both run the same commands, the same program and the same data folder (D23).

door TWO · NXSPOOF.app

Everything chains

  • Double-click: the page opens (or comes back), showing the run if there is one
  • ▶ Start: one password window, setup's fixes included if needed (🛠️ Fix and start)
  • ■ Stop, ⚙️ Configure, consoles, past runs, 📖 Help
  • Close the page: the dialog if NXSPOOF runs, then it tidies up by itself
  • Every button that needs your password runs a real nx_spoof.py command
door ONE · the Terminal

Plain parts, flags, nothing chained

  • sudo python3 -B nx_spoof.py start: start, the answer, back to the prompt (--fix, --anyway, --no-firewall, --manual-sharing, --keep-sharing…)
  • nx_spoof.py stop: no password (the run is you)
  • nx_spoof.py follow: watch it live (--console casual, --no-color)
  • doctor, setup, uninstall, cleanup, check, running… (every command)

The menu, screen by screen

menu.command: numbers on every screen, from 1; b back, q quit. 🔑 asks for your password. What doesn't fit the moment is grayed out (here: the items for while NXSPOOF runs) but still answers if you pick it: Start while it runs says "already running" at once. Each item is one plain thing: an nx_spoof.py command, a tool, or opening a file. The window opens at 100 × 32; what's wider is cut, never wrapped.

Starting: the one way

Menu 1 runs sudo python3 -B nx_spoof.py start; the page's ▶ Start runs the same command through macOS's password window. Then:

Stopping, and watching

  • Stop: ■ Stop, menu 2, or nx_spoof.py stop (no password). It leaves the run a note (stop.json, read every half second) and sends a signal too, then waits until the run has stopped. The run: firewall out, summary, Internet Sharing off, the cable out if it put it in, Stopped.
  • Watch: menu 3 (technical) or 4 (casual), or nx_spoof.py follow: the newest run's records, live, from its first line. Ctrl+C or closing the window only stops watching.
  • Is it running? nx_spoof.py running: the lock's answer, yes or no (the menu's status line uses it).

What runs as root

Your password starts NXSPOOF as root, but it keeps root only where it must. Right away it splits in two processes (D24):

root

The keeper

Only four kinds of jobs, each request checked: turn Internet Sharing on and off; load, read and remove NXSPOOF's own firewall rules for the hotspot (it builds them itself); plug the virtual cable in and take it out; open the DNS and web ports on the hotspot's address and hand them over. It listens for the run's heartbeat: a run silent for 30 seconds is frozen, so the keeper ends it and cleans up.

you

The run

The DNS answers, the test page, watching the consoles, the logs: the part that reads what consoles send never has root, and its files are yours. If it ends without cleaning up, the keeper does, and adds NOTE the run ended without cleaning up … - the keeper did: … to its log.

The log's LOG privileges: … line says which way it ran. --no-keeper keeps the whole run root in one process (for comparison; stopping it then needs sudo). The dashboard never runs anything as root by itself: macOS's own password window does, one action at a time.

Why both doors

The dashboard is what most people want: buttons, a password window, plain words. The Terminal is always there, for whoever likes to see every line, pass a flag, or script it, and as the fallback when something about the app goes wrong. What's deliberately skipped (D23): installing into /Applications, a root helper that never asks for the password, signing, a bundled Python, self-updating. The folder is NXSPOOF, and it runs from wherever you put it.
