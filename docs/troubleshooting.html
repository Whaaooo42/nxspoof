Troubleshooting

Type what you see: an error number, a word from the log, a button's name. Every word must match. Not listed, or the fix didn't help? 🐞 Report makes a report for a GitHub issue. The technical lines (WIFI, DHCP, DNS…) are in the dashboard's Technical log, or the run's log file (menu 6 → 2).

Starting

NXSPOOF.app, menu.command or a file in scripts/ won't open ("unidentified developer")
Right-click it → Open → Open. Only needed once per file.
NXSPOOF.app opens nothing at all / you clicked Don't Allow for the folder
System Settings → Privacy & Security → Files and Folders → NXSPOOF: turn on Documents Folder (or the folder nx-spoof is in). Or use scripts/dashboard.command (the dashboard with a Terminal window).
Start lists what isn't ready, ending with ✋ "Not ready yet"
Each ✋ line says what's missing. 🛠️ Fix and start on the page (one password for both), or menu 1 asks "Let setup fix what it can, then start?" (start --fix), then "Start anyway?" (start --anyway).
NXSPOOF is already running (process N): nothing done. / ▶ Start says already running or starting
One run at a time (the lock): two would fight over the firewall and the ports. A run started from the menu shows up on the dashboard within a second; stop it there (■ Stop), with menu 2, or nx_spoof.py stop, then start again.
Pressed ▶ Start but it still says ▶ Start, or Starting… for a long time
Look at the header: type your password in the macOS window (the window may be behind your browser), or waiting for NXSPOOF to come up. From the menu: type your password in the Terminal (nothing shows while you type).
The dashboard's log says start cancelled
The password window was closed with Cancel. Press ▶ Start again.
NXSPOOF didn't start - what the start said:
The lines under it are what nx_spoof.py start printed (the data folder's logs/.page_start.txt): its ❌ line says why (this Mac not ready, the hotspot didn't come up within 60 s…). Fix that, or try menu 1, which prints the same answer in the Terminal. A wrong password doesn't get here: macOS asks again.
couldn't start NXSPOOF: macOS said: …
macOS refused the password window (for example an account that isn't an administrator). Use an administrator account, or menu 1.
couldn't prepare NXSPOOF's data folder (…) after ▶ Start
The dashboard couldn't refresh the program copy in ~/Library/Application Support/NXSPOOF/program/ (a full disk, or a file there that isn't yours). Menu 1 works meanwhile.
FATAL virtual cable: couldn't plug it in / 😕 "I couldn't plug in the virtual cable"
Thunderbolt Bridge lost its fixed address. ⚙️ Configure → 🛠️ Fix selected (or menu 7 → 2), then ▶ Start again.
settings.json has an error on line X, column Y
Fix that spot: usually a missing or extra comma, or single quotes instead of double quotes.
FATAL … port 53 or port 80 in use
See what's using it: sudo lsof -nP -i :53 (or -iTCP:80), and quit it (e.g. brew services stop dnsmasq).
switching to plan B (pf redirect)
Fine: NXSPOOF worked around a port conflict by itself (DNS on 5354, the firewall redirects). What matters is READY.
plan B failed
sudo ifconfig bridge100 alias 192.168.2.254 255.255.255.255, then sudo python3 nx_spoof.py start --ip 192.168.2.254, and set the console's Manual DNS (below) to 192.168.2.254.

This Mac (setup, undo, clean up)

Setup says "needs admin rights"
Use the dashboard's 🛠️ Fix selected (or menu 7 → 2): it asks for your password. Not python3 nx_spoof.py setup without sudo.
Configure's This Mac column says "Setup waits until NXSPOOF stops" / a run is active: nothing done
Setup, undo and clean up wait while NXSPOOF runs or starts (setup would pull the bridge out from under it), or while another This Mac task runs. Stop the run first, or wait for the task.
The bridge's address is in a network this Mac already uses
Your home network (or another adapter) uses the same range. ⚙️ Configure, Thunderbolt Bridge's line: pick another address (10.254.0.1 or 192.168.254.1), then 🛠️ Save and fix.
The hotspot has no password (SHARING hotspot: … password MISSING)
System Settings → General → Sharing → ⓘ next to Internet Sharing → Wi-Fi Options…: a password of at least 8 characters, WPA2/WPA3 Personal. NXSPOOF never sets it: macOS keeps it in its keychain.
😕 Couldn't set up this Mac: it stopped half way (or undo, clean up)
The command ended without its closing line. The dashboard's log has what it wrote (… ended without its closing line - what it wrote:); 🐞 report it. Meanwhile menu 7 → 2 (or 7 → 3, 7 → 4) does the same in a Terminal window, everything visible.
Setup says virtual cable: FAIL - not plugged in yet
Normal before setup plugs it in (the next line says fixed). Only plugged in, but Thunderbolt Bridge has no fixed address yet is a real problem: run setup again.
SETTINGS not imported: NXSPOOF or its dashboard is open
The open dashboard (or a run) owns settings.json while it's up. Use the dashboard's ⚙️ Configure → 📥 Import settings…, or close it first.
Import says the file has an error on line X, column Y
The file isn't valid JSON (often a missing or extra comma). Nothing was changed. Fix that spot, or export a fresh copy.

During a run

SHARING the hotspot went DOWN (…) - putting it back / ⚠️ The hotspot stopped
macOS dropped the hotspot (on Nov 18 it lost the virtual cable). NXSPOOF puts it back by itself: try 1: virtual cable plugged back in, Internet Sharing turned ON again, then the hotspot is UP again with a new self-test; consoles usually rejoin by themselves. It never gives up: after three tries it goes on every 60 s until the hotspot is back or you Stop (a Mac asleep comes back this way). Down for long: Stop, start again, and 🐞 report it (the report has what came before).
NOTE this Mac slept (about …) - stopping / 😴 Your Mac went to sleep, so I stopped
Normal: a sleep ends the run (D32). A sleeping Mac takes the hotspot and the consoles with it, and on waking macOS rejoins your home Wi-Fi; NXSPOOF stops cleanly instead of taking that away again. A run keeps the Mac awake (the log's keeping this Mac awake line), but closing the lid still sleeps it. ▶ Start again when you need it. --allow-sleep lets an idle Mac sleep (and so end the run) on purpose.
I turned Internet Sharing off in System Settings, and it came back on by itself
While NXSPOOF runs, it puts its hotspot back when it disappears. To end it, press ■ Stop (or menu 2): NXSPOOF turns sharing off itself.
SHARING the hotspot's name changed: "…" now, "…" at the last run / ⚠️ Your hotspot is now called …
Someone renamed the hotspot in System Settings (NXSPOOF never does). Each Switch has to join the new name, with the password; or put the old name back in Wi-Fi Options.
NOTE the run ended without cleaning up (…) - the keeper did: …
The run stopped abruptly (a crash, a forced quit, or frozen for 30 s), and NXSPOOF's root part, the keeper, cleaned up: nothing is left on. If the line says couldn't …, press 🧹 Clean up (or menu 7 → 4). 🐞 Report it (the report has what came before).
PROBLEM NXSPOOF's root part (the keeper, process …) went away - stopping
The keeper was stopped by force, so the run stopped too: it can't undo the firewall or sharing without root. The dashboard's banner offers 🧹 Clean up.
The red banner: the last run never reached its end, or Internet Sharing is still on
A run crashed, the Mac restarted during a run, or it was stopped by force. 🧹 Clean up (your password): firewall rules out, sharing off, the cable out. Not now hides it until the dashboard opens again.
sudo pfctl -s info says Status: Enabled after NXSPOOF stopped
Each run gives back its hold on pf (its pfctl -E token) when it stops, so pf goes off again unless something else holds it (sudo pfctl -s References lists who). Runs from before 2026-11-24 didn't: their tokens stay until the Mac restarts. Restarting clears them.
Internet Sharing still ON after NXSPOOF stopped / the Mac has no internet
No internet is expected while sharing is on. After a stop: 🧹 Clean up, menu 7 → 4 or sudo python3 nx_spoof.py cleanup, or turn it off in System Settings.

The hotspot

Stuck on …not found yet / ⏳ "Waiting for the hotspot"
Sharing didn't really start (start gives up after 60 s; its FATAL line lists the network interfaces macOS has, which 🐞 Report includes). Check Setup step C, and turn sharing OFF, wait 5 s, ON. Still failing: the virtual cable may be missing (python3 nx_spoof.py link status).
SHARING could not turn it on automatically or still not up after 30 s
System Settings → Sharing opens for you: turn Internet Sharing on by hand (from Thunderbolt Bridge, to Wi-Fi). NXSPOOF carries on by itself. 🐞 Report it (the report has the SHARING line).
No "Thunderbolt Bridge" in Share your connection from
Add it (Setup step B). Or pick an Ethernet adapter that is not plugged into your router.

A console connecting (in the order the lines appear)

Console error 2110-1100 / no WIFI … joined line
The console never joined the Wi-Fi radio: not the firewall. Rescan on the console and pick the hotspot, switch its Wi-Fi off and on, or try channel 1 or 6. Once, a retry fixed it.
WIFI line but no DHCP line
Start once with --no-firewall to compare, then 🐞 report it.
DHCP line but no DNS lines
On the console: the hotspot → Change Settings → DNS Settings → Manual → Primary and Secondary 192.168.2.1 → Save → Test Connection.
DNS lines but no HTTP line
The Mac's own firewall: System Settings → Network → Firewall → Options → allow python3, or turn off "Block all incoming connections".
FIREWALL WARNING instead of FIREWALL ON
DNS and web blocking still work, but the firewall may not be blocking: another firewall or a VPN may be using pf, macOS's packet filter. Quit it for one run to compare, and 🐞 report it.
Everything looks right but the console still says no internet
Note the error code (2xxx-xxxx). The run's log (data/logs/) has the rest.

Names, Wi-Fi tracking, FTP

My console shows as Unknown console / 🙋 "A console I don't know"
Its mac in settings.json is wrong or missing. Add it from its card (➕ Add to settings.json), or copy the MAC from the WIFI … joined line.
A console left but no left the Wi-Fi line
Wait 16 seconds: the longest it takes. Never comes: 🐞 report it, with the time it left.
WIFI the Wi-Fi watcher saw no console join or leave / ⚠️ I couldn't see consoles joining the Wi-Fi
Your macOS words its Wi-Fi log lines differently from the ones NXSPOOF knows. Everything else works; only join and leave times are missing. 🐞 Report it: the report says which macOS.
DHCP … lookups came from addresses no DHCP lease names / ⚠️ I couldn't tell which console was which
Your macOS may keep its DHCP lease file somewhere else, so consoles show as addresses. Everything else works. 🐞 Report it.
FTP server is UP never appears
Check the FTP app is running on the console and its port matches the console's (or the global) FTP port.
FTP server busy (a program on this Mac is connected to it…)
Normal: FileZilla is using the console's FTP server, which takes one connection at a time. It still counts as UP.
FileZilla connects and logs in, but listing folders or transfers hang
Use passive mode (FileZilla's default: Site Manager → Transfer Settings → Passive). In passive mode your Mac opens every connection, which the firewall lets back; in active mode the console would connect back to the Mac, and the firewall blocks connections a console starts.
open_filezilla is on, but FileZilla isn't in /Applications / "Open in FileZilla" is missing
The button only shows when that console's FTP server is UP and FileZilla is in /Applications. Install it there, or turn open_filezilla off.

The dashboard

port 8800 is used by another program: the dashboard is on … from now on
Nothing to do: the dashboard took a free port and remembers it (the data folder's dash.json). NXSPOOF.app and menu 5 open the right one.
The browser didn't open
Open http://localhost:8800 yourself (or the port in the data folder's dash.json).
The page says "Can't reach the dashboard any more"
The dashboard isn't running anymore. Open NXSPOOF.app again: a run still going shows up within a second, and if a crash left something on, the red banner offers 🧹 Clean up.
NXSPOOF.app just opens the page that's already there
One dashboard at a time: opening it again brings the open one back.
I closed the dashboard's page while NXSPOOF runs
A few seconds later a macOS dialog asks Stop NXSPOOF or Keep running (the default, also when nobody answers within 2 minutes). Either way the dashboard closes; a run that keeps going shows up on the next dashboard you open, its whole log from the first line. Opening NXSPOOF while the dialog is up keeps the dashboard.
The browser tab shows a gray letter instead of NXSPOOF's green "ok"
Safari's icon cache is stuck (other sites show letters too). Quit Safari (⌘Q), then in Finder, Go → Go to Folder… ~/Library/Safari/ and move Favicon Cache to the Trash. Open Safari again and reload the dashboard. Removing the site's website data doesn't touch icons.
The log looks empty in Casual
Only meaningful events show in Casual. Switch to Technical to see everything.
Adding or editing a console says "another console is already called…", "please give it a name", "color must be…", "the FTP port must be…"
Pick another name, type one, choose a color from the list, or a port from 1 to 65535. Nothing was written.
Adding a console says "that console hasn't connected during this run"
The card's form is for consoles seen in this run. Let it connect, or use ➕ Add a console with its MAC address.
I removed a console by mistake
If it connected during this run, its card now offers ➕ Add to settings.json: add it back (its notes are gone). Otherwise the latest import backup or the run's log has its MAC address.
A setting I changed didn't take effect
Its row says next start: it's saved and applies when NXSPOOF starts again. A blue badge (e.g. --no-firewall for this run): an option given at start wins for this run.
Saving says "must be at least…", "must be a whole number", "must be one of…"
Use a value in the range or list it gives. Nothing was written.
Where did settings.json and logs/ go?
Into NXSPOOF's data folder, ~/Library/Application Support/NXSPOOF/ (so ▶ Start works wherever the nx-spoof folder is). The data shortcut opens it; so does menu 6 → 3. A settings.json.old in the nx-spoof folder means the data folder already had one: the data folder's is used.
🐞 I want to report a problem / none of this helped
On the dashboard, 🐞 Report (top right): NXSPOOF makes a report with this Mac, its setup and the last runs' warnings and problems, and shows it first. Console names, MAC addresses (all but their maker part), the hotspot's name, your name and your Mac's name are replaced; read it anyway. Copy it, open a new issue on NXSPOOF's GitHub page and paste it, with what happened in your own words. From the Terminal: menu 6 → 4, or python3 -B nx_spoof.py report (it's also saved in data/logs/reports/; --full adds the last run's whole log).
